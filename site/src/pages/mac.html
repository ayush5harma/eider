Eider on the Mac

Eider.app is laid out like the Mac App Store and shares one engine, EiderKit, with the eider command, so the two behave the same.

Apple silicon only, macOS 14 or later. Installing needs no Xcode or Command Line Tools: the install path runs only codesign, unzip and lsregister.

The app

Five places in the sidebar:

  • Library: a grid of what you installed.
  • Updates: every installed app a source has a newer version of, with its release notes, Update and Update All. The count shows on the sidebar and on the Dock icon.
  • Browse: the apps your sources offer, each with a product page.
  • Activity: downloads and installs, one progress ring each.
  • Sources: add, refresh and remove them, import and export the list.

Dropping an .ipa on the window installs it. An eider://source/<url> or eider://install/<url> link always asks before it does anything. The install sheet lets you choose the destination folder, the interface size and extra options such as dylibs to link in. On macOS 26 and later the window uses Liquid Glass, with a material fallback on macOS 14 and 15; lists stay plain so catalogs with thousands of apps scroll smoothly, and icons load only for rows on screen. The icon is a layered Icon Composer icon: on macOS 26 and later the system adds its glass and the Default, Dark, Clear and Tinted looks; macOS 14 and 15 get a flat version drawn from the same shapes.

How an install works

  1. Unpack the archive, refusing unsafe entries, and find the one Payload/*.app.
  2. Read Info.plist; refuse an unsafe bundle id, executable or name.
  3. Refuse any binary that is still FairPlay-encrypted.
  4. Convert every Mach-O: thin to arm64, rewrite the platform to Mac Catalyst (each binary keeps its own SDK version), repoint the Swift UIKit overlay. This is done in pure Swift, with no lipo, vtool or install_name_tool.
  5. Edit Info.plist (MinimumOSVersion, the Mac idiom if asked, name and id).
  6. Link the shims into the main executable.
  7. Sign every binary and nested bundle ad hoc, then the app with a sandbox entitlement set plus the app's own app-group ids, and verify each signature strictly.
  8. Stage the app on the destination volume, move any earlier copy to the Trash, move the new one in, and record it in library.json.
  9. Write the interface size into the app's own preferences.

Only the app-group ids are copied from the IPA's original entitlements. application-identifier, the team id and keychain groups belong to a developer account, and an ad hoc signature that claims them is killed. Each group id must be plain letters, digits, ., -, _ (at most 255 bytes, at most 32 groups); others are dropped with an install warning.

A bundle already at the destination is replaced only if Eider installed it or you pass --force, and the old copy goes to the Trash, never deleted. An update of an installed app installs exactly the version it found, keeps the installed options and data, and stops before placement if the IPA's final id differs, so an update can replace the app it was asked to or nothing.

The legacy/ folder of the repository holds the shell installer this came from and the measurements behind these steps.

The shims

An ad hoc signature gets no keychain, no app groups, no usable OpenGL and no CallKit, so small libraries are linked in (built by Scripts/build-shims.sh):

Keychain
An emulated keychain stored in the app's container, so a sign-in survives a relaunch. --no-keychain opts out. It treats request flags such as kSecUseNoAuthenticationUI as flags, not item attributes.
App groups
A writable app-group folder inside the app's own container, because macOS denies an ad hoc signed app its real ones. Each signed group's preferences (NSUserDefaults suites and the CFPreferences functions) are stored under their own domain in the container, since cfprefsd refuses writes to a domain named after one of the app's groups. Apps that read their team id from their own signature get an answer with the same prefix the keychain shim uses.
OpenGL ES
Run-time GL lookups are answered by OpenGL ES instead of desktop OpenGL, for apps that link OpenGL ES.
CallKit
CallKit keys its clients by an application identifier an ad hoc signature cannot carry, so the system refuses the app's call provider and crashes when a call is placed. For apps that link CallKit, the app's own “use CallKit for this call?” checks answer no, so an app with its own call path (WhatsApp) takes it. An app with no such fallback gains nothing.
Camera
For apps that link AVFoundation, a requested frame rate outside what the active camera format supports is moved to the nearest supported one. iPhone-style variable rates against a fixed 30 fps Mac webcam otherwise crash the app at the first video frame.
Per-app quirks
Some apps misbehave because of their own code. A table (AppQuirks.all) holds rows of bundle id, class, selector and a forced BOOL return, written into the bundle at install time and applied only when the class and method exist and the method is a no-argument BOOL getter. The first row is YouTube's, whose launch sequence loses the race with Catalyst's late first scene and leaves a blank window. Adding an app is one row, not a new shim; the architecture notes say how.
Keychain-fix tweaks
A bundled “keychain fix” tweak library is replaced by an empty one so it cannot defeat the keychain shim.

The keychain shim (unless you opt out) and the app-group shim are always linked; the OpenGL ES, CallKit and camera shims are linked only when some binary in the bundle links the framework each one corrects.

Interface Size

An iPad app under Mac Catalyst draws at 77% (“Scale Interface to Match iPad”), so its 44 pt controls and 11 pt labels come out at 34 pt and 8.5 pt, smaller than Apple's own apps. UIKit reads two keys from the app's own preferences at launch: iOSMacScaleFactor (a number that replaces the 77%) and UIUserInterfaceIdiomMac (the Mac idiom, 1:1, without touching UIDeviceFamily). Eider writes them into the app's container, never into the bundle, so the signature is untouched, a change takes a relaunch rather than a reinstall, and an update keeps it.

ChoiceMeaning
Auto (default for new installs)100% on the built-in display, so UIKit points map 1:1 to Mac points as Apple's own apps draw. On an external display, which sits further away, Auto scales so a point covers the same visual angle as on a MacBook's built-in display at its default resolution (127 pt/in at 50 cm against about 65 cm), within 100-125%: 110% on a 27-inch display at “looks like 2560 x 1440”. Worked out when applied and each time Eider opens.

Mac idiomThe Mac idiom, 1:1 with the display. Changes control styles and can break iPad layouts; it was checked only on YouTube's first screens.

Set it in the install sheet, in each app's menu in the Library (Interface Size), or with eider scale. Apps installed before Interface Size existed stay at 77% until you pick a size; a one-time Library banner offers “Use Auto”. Measured with YouTube 21.47.6 on a built-in Retina display: at Auto, its Back and Search controls measure 44 x 44 pt instead of 33 x 33.

Library

The Library is an icon grid of the apps Eider installed, recorded in library.json. Each app has Open, Update (when one is available), Interface Size, Diagnose, Show in Finder and Uninstall in its menu. A Show Updates button appears when any app has a newer version. Uninstall moves the app to the Trash and, if you ask, its data container too; moving another app's container needs Full Disk Access. The same operations are available as eider list, open, scale and uninstall.

Updates and Update All

A catalog install or update records where the app came from: the source's address and the entry's id and name as the source lists them. That origin is the only link back to the entry, because a source may list an app under another id than the app has (an entry listed as com.kdt.l!vecontainer installs as com.kdt.livecontainer). To find an update, Eider takes per installed app:

  1. the origin's entry, if that source is still added and still lists it;
  2. otherwise, for an app installed before origins were recorded, the entries with its bundle id in the source it recorded;
  3. otherwise the entries with its bundle id in any source that lists one name under that id. Where several apps share an id, which of them an installed app is cannot be told, so nothing is offered.

A known origin is never widened to other sources. The offer is the newest candidate, only if it is newer than the installed version, and it names its source and entry. Commit-hash versions are never offered over numbered ones. The Updates page shows installed and new versions, the source, date and size, an expandable What's New and an Update button; Update All runs one app at a time through Activity. Updates keep the installed options and data. The list is worked out off the main thread at each reload, and the count shows on the sidebar and the Dock tile. eider list and eider update [--all] use the same matcher.

Launch diagnostics: eider doctor

eider open launches an installed app and confirms it stays up; eider doctor does the same and, if the app does not stay up, says why. An app counts as running once it has stayed up for 8 seconds (--settle <seconds>, which must be less than --timeout, default 20). Use a longer settle for an app that fails late:

eider doctor com.example.app
eider doctor com.example.app --settle 15

An app that dies sooner gets a diagnosis with a stable code, read from the system log and crash reports. Codes include:

  • launch.uncaught_exception: an Objective-C exception, with the exception, its reason and the app binary that threw it. Checked first, because an exception proves the app ran past dyld and code signing.
  • launch.library_not_loaded: a library the app needs could not be loaded.
  • launch.system_policy: a system policy refused the launch. A crash is not blamed on a sandbox denial that refused some other process.
  • launch.window_not_attached: the app stays up with an empty window because it built its first screen before macOS gave it a window. It is reported only when both signals are present: UIKit's “whose view is not in the window hierarchy” in the log and a window holding nothing but its title bar and container groups. Reading the window needs the Accessibility permission for the terminal or for Eider. Such an app needs a per-app workaround, so please report it.

The code strings are a stable contract: codes are added, never renamed. With --json, the diagnosis is machine-readable.

Not in Eider

Game controls through PlayTools exist only in the legacy/ shell installer, not in Eider. See limitations for what else does not work.
