Security and privacy

Sources, IPAs, their Info.plist files and file names are untrusted input. Eider is built so that a source can only make it download a file, and installing that file never executes anything from it.

The no-piracy stance

Use Eider only with apps you have the right to run: apps you own, hold a licence for, or that are open source or otherwise freely distributable.

  • Eider ships no sources. It has no built-in list of apps and no default repository. You add the sources you trust.
  • Eider decrypts nothing. Binaries still encrypted with FairPlay (what the App Store delivers) are refused. It starts from an .ipa that is already decrypted and does not explain, link to or provide any way to do that step.
  • A source must only list IPAs its author has the right to distribute. Obtaining or decrypting an App Store binary may breach Apple's terms of service and, depending on where you are, local law; weighing that is yours to do.
  • Eider is not a jailbreak tool and not a FairPlay remover. Its own test apps are open-source apps from their own releases, never cracked or paid apps.

Security model

Network and URLs

  • https only. http is allowed to this Mac only, and only for a source you added by a loopback address and the items inside it. Rules are checked on every redirect. See the URL policy.
  • A deep link (eider://) always asks first and never carries a file URL or loopback address. Imported lists are held to the same rule.
  • Downloads are checked against a published SHA-256 and the first hash an address ever served, and resume only against the same address and version.

Archives and installs

  • Archive entries may not escape the extraction folder. Symlinks are recreated only with relative targets without ... The 8 GB cap counts bytes actually written.
  • Nothing from an IPA runs during install. Names are stripped of control and bidi characters, and bundle ids are validated before they become paths or signing inputs.
  • Encrypted binaries are refused.
  • A catalog install must yield the app the source listed. A bundle already at the destination is replaced only if Eider installed it or you pass --force, and the old copy goes to the Trash, never deleted.
  • Signing gives an app a fixed sandbox entitlement set plus its own app-group ids. Entitlements that belong to a developer account are not copied.
  • The install path runs only a short list of system programs (codesign, unzip, ditto, open, log, lsregister), never developer tools.

Secrets and trust on iOS

  • Certificate passwords, the manifest server's URL (its path is a secret) and a pairing file are kept in the Keychain on the device only, never in a plist or database. The pairing file is never a file.
  • The local root that signs the install server's certificate is name-constrained to loopback and private address ranges plus localhost, with its private key held in the Keychain and never exported. Even a leaked key could not vouch for a public site. Eider does not ship or download anyone's published private key.
  • The install server answers only the iPhone itself, serves one path under a random 128-bit token per install, and stops shortly after the IPA has been served. See the details.

Known security-relevant limits

  • The Mac keychain shim stores logins as a plain file under ordinary file permissions in the app's container, not behind your login password.
  • Eider's own releases are ad hoc signed and not notarized (you approve the first launch in System Settings).
  • A checksum in a source is checked when present, but a source without one is not a verified source. Install only from sources and IPAs you trust.

Reporting a vulnerability

Use GitHub private vulnerability reporting: open the repository's Security tab and choose “Report a vulnerability”, or go straight there. Do not open a public issue. Include the Eider version, macOS version and the smallest input that reproduces the problem.

In scope: archive extraction that escapes the folder or the size caps; downloads that bypass the https-only rule, a redirect that leaves the policy, or a checksum mismatch that is accepted; a source or deep link that crashes Eider, reads local files, or makes Eider fetch something it should not; anything that makes Eider run code from an IPA during install or sign, place files outside its own state folder, or install an app meant to be refused. Out of scope: vulnerabilities in an app you chose to install, and the fact that releases are ad hoc signed and not notarized. This is a small volunteer-run project; reports are acknowledged as soon as practical and fixes ship in the next release. The full policy is SECURITY.md.

Privacy

  • No analytics, no telemetry, no accounts. The source code contains no analytics or crash-reporting code, and Eider has no server of its own.
  • Your data stays on your machine. On the Mac, Eider keeps its state (your source list, saved catalogs, downloads, the library record and an image cache) in its own folder under ~/Library/Application Support/Eider. brew uninstall --zap --cask eider removes it.
  • The network traffic is yours. Eider contacts the addresses of the sources you add, the download and image addresses those sources list, and the address of an IPA you give it. On iOS it also asks Apple's OCSP responder whether a certificate is revoked, contacts the manifest server you configure, and can open LocalDevVPN's App Store page. The pages of this site are static, with no scripts or cookies of their own.
  • What the sources see. A source's host sees the requests Eider makes for it, as any web server sees any client. Choose sources accordingly.
  • Certificates and pairing files are secrets. Keep test copies outside any repository, and never share them.
