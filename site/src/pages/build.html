Build from source and licences

Eider is one Swift package. It needs an Apple silicon Mac, macOS 14 or later and a Swift toolchain (Xcode or the Command Line Tools).

Building and testing

git clone {{repo}}.git
cd eider
swift build
swift test
Scripts/build-shims.sh      # compile the shims into build/shims
Scripts/call-shims.sh       # the CallKit and camera shims, no app or camera needed
Scripts/engine-e2e.sh       # install engine, judged by effect
Scripts/e2e.sh              # source, install, update, doctor, uninstall
Scripts/make-app.sh         # assemble and ad hoc sign build/Eider.app

EIDER_E2E_CRASH_CHECKS=1 Scripts/e2e.sh adds the crash checks (missing library, throwing tweak), one crash window each. Scripts/make-app.sh --configuration debug builds a debug bundle. Scripts/release.sh <version> builds release archives locally; it never tags, pushes or publishes. The end-to-end scripts install only into temporary folders, and tests and scripts set EIDER_HOME so nothing touches your real application support folder. They run eider as on a Mac with no developer tools.

Building Eider for iOS

The iOS app is an Xcode project in Apps/EiderMobile, generated from project.yml with XcodeGen and committed. Signing values are not in the committed project because the repository is public: the target reads EIDER_TEAM, EIDER_PROFILE, EIDER_IDENTITY and EIDER_SIGN_STYLE from a gitignored Local.xcconfig (see Local.xcconfig.example) in Xcode, or from the environment in Scripts/ios-device.sh:

TEAM=... PROFILE=... IDENTITY=... DEVICE=... Scripts/ios-device.sh [Debug|Release]

It builds the app and installs it on a connected device with devicectl. The provisioning profile must cover io.github.ayush5harma.EideriOS (a wildcard profile does) and the device. To check the iOS libraries without a device: xcodebuild -scheme EiderInstall -destination 'generic/platform=iOS' build (the same works for EiderCore and EiderSign). Never commit a certificate, profile, .p12 or password.

How the code is organised

Eider.app (Sources/EiderApp)      eider CLI (Sources/eider)
            \                        /
                 EiderKit (Sources/EiderKit)
                          |
                 EiderCore (Sources/EiderCore)

EiderCore holds the platform-neutral half (catalog, downloads, update matching, paths, image cache, browse index) and also builds for iOS. EiderKit re-exports it, so the command line tool and the Mac app import EiderKit alone. EiderSign and EiderInstall are the iOS signing and install libraries. Each EiderKit module is one directory with one owner:

DirectoryHolds
Support/paths, hashing, version, display text, bundle-id check, image cache, process runner
MachO/Mach-O reading and editing in pure Swift
Engine/IPA to installed app
Library/registry of installed apps, uninstall
Catalog/source formats and the source list
Downloads/fetching IPAs
Updates/installed version against catalog version
Browse/the catalog flattened for search
Diagnostics/why an installed app did not launch

The rules every module follows (state under one folder, allowed external programs, untrusted input, typed errors with stable codes) are in docs/ARCHITECTURE.md; the contributing guide is CONTRIBUTING.md. Commit messages use <type>: <why>, and no code from GPL or AGPL projects is accepted.

Building this site

The site is plain HTML and CSS in site/, built by a small standard-library Python script and deployed by a GitHub Actions workflow:

python3 site/build.py              # writes site/dist
python3 site/check_links.py        # checks every link and anchor in site/dist
python3 -m http.server -d site/dist
