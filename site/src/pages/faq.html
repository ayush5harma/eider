Limitations, known issues and FAQ

Eider is early software. This page collects what does not work, what the release notes list as known issues, and answers to the questions people ask first.

What does not work

  • Encrypted IPAs are refused. App Store downloads are FairPlay-encrypted. Eider decrypts nothing.
  • Push notifications, iCloud and in-app purchase need a real signature and entitlements; under an ad hoc signature they do not work.
  • App extensions are outside the shims. --remove-extensions drops them, which often helps an app that will not sign or open.
  • Logins stored by the keychain shim are a plain file under ordinary file permissions in the app's container, not behind your login password.
  • Game controls through PlayTools exist only in the legacy/ shell installer in the repository, not in Eider.
  • An app built for a newer iOS than it adopted behaves as it would there. Some apps break under --mac-idiom.
  • Apple silicon and macOS 14 or later only. An x86_64-only or simulator-only IPA will not install.
  • Calls. The CallKit shim only helps apps with their own call path (WhatsApp is the example); an app with no such fallback gains nothing.

Known issues

From the release notes of 0.1.10 and 0.1.11, the latest releases that carry a list:

  • A source added from a local file or a local network address cannot be imported back from an export. Add it by hand.
  • Uninstall with “Also remove its data” cannot move another app's data container to the Trash from inside the app without Full Disk Access.
  • App-specific issues found in a compatibility sweep of open-source apps, still open: Delta crashes at launch in its own code; iTorrent quits itself on its first launch and runs on the second; PPSSPP hits the sandbox's shared-memory rule.
  • Mac idiom was only checked on YouTube's first screens. It changes control styles and can break iPad layouts, so it is not the default.
  • An app that stays up with an empty window needs a per-app workaround; eider doctor reports it as launch.window_not_attached so it can be reported.
  • Apps installed before a release that adds a shim need reinstalling to get it.

Older notes also list that the Library held one app per bundle id (0.1.7), so installing one YouTube-variant over another replaces it, and that Update and Update All had not been run against a real app with a newer version (0.1.7 and earlier). Later notes do not say these were resolved, so treat them as unverified.

What has been tried

  • iSH was installed from a 17,430-app source, opened from the Library and seen to stay running (0.1.1).
  • YouTube 21.47.6: installed, the blank window fixed with a per-app quirk row, and its controls measured at full size at Auto interface size (0.1.8, 0.1.9).
  • A sweep of ten open-source apps from their own releases, launched from Finder, killed with kill -9 and relaunched (0.1.10). Opened with content: Feather, Jitterbug, LiveContainer, Mirarr, SideStore, StikDebug, UTM SE.
  • The CallKit and camera shims link and verify; the 0.1.1 notes say no call had been placed yet.

Compatibility is per app. If one does not work, run eider doctor <bundle-id> and file an app compatibility report.

Pre-release and not yet verified

  • Every release to date is marked pre-release, with the label “Still early software”.
  • Eider for iOS is unreleased; its full on-device flow with the manifest server set inside the app, and the whole pairing method, are not verified. See its status.
  • The icon had not been seen on macOS 14 or 15 as of 0.1.4; the Dock badge had been checked as a count, not on a live Dock.
  • Eider's own end-to-end checks install only into temporary folders; the unit and end-to-end counts in each release's notes say what ran.

FAQ

What is Eider, in one sentence?

A Mac app and command line tool that reads AltStore and PlayCover style sources, downloads the decrypted iOS IPAs they list, and installs each as an ordinary Mac app on Apple silicon.

How is it related to Feather and PlayCover?

It is inspired by Feather (sources) and PlayCover (the install mechanism) and is not affiliated with either. It contains no code from them or from PlayTools, which are GPL or AGPL; Eider is MIT licensed.

Does Eider include any apps or sources?

No. It ships no sources. You add the ones you trust.

Can I install apps from the App Store with it?

No. Those IPAs are encrypted and Eider refuses them. It does not decrypt anything.

Why does macOS warn me when I open it?

Eider is ad hoc signed, not notarized. Open it once and approve it in System Settings > Privacy & Security.

Do I need Xcode?

No, not to install apps. The install path runs only codesign, unzip and lsregister. You need Xcode only to build Eider for iOS or to build from source (a Swift toolchain).

Why do iPad apps look small?

Mac Catalyst draws iPad apps at 77%. Eider's Interface Size sets a larger scale (Auto by default for new installs). See Interface Size.

My app quits right away. What now?

Run eider doctor <bundle-id> (add --settle 15 for an app that fails late). It reports a stable code such as launch.uncaught_exception with the reason. Try --remove-extensions, --no-keychain or --reset on a reinstall, and report the app if it still fails.

Does an update delete my data?

No. Updates keep the installed options and data. --reset on install is what clears saved data, and it needs the app to be quit.

How do I move my sources to another Mac?

Export from the Sources page (or eider source export -o sources.json) and import there. See import and export.

Can Eider for iOS install apps from the App Store?

No. It signs IPAs you supply or download from your sources with your own certificate. It has no way around Apple's signing requirements, and a free or paid developer certificate has the limits Apple sets on it.

Why does the iOS app need a manifest server?

Because on iOS 27 the system installer refuses a manifest URL served by the iPhone itself. The manifest must come from another host; the IPA can come from the iPhone. See the measured rule.

Does Eider collect any data?

No. See privacy.

How do I uninstall Eider?

Use brew uninstall --cask eider, or move Eider.app to the Trash. Apps Eider installed are separate apps; remove them with eider uninstall or from the Library first. brew uninstall --zap --cask eider also removes ~/Library/Application Support/Eider.

How can I help?

Report app compatibility results and bugs with the issue templates, and read CONTRIBUTING.md before sending code. Do not copy code from GPL or AGPL projects such as Feather, PlayCover, PlayTools, AltStore or SideStore.
